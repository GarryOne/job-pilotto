# The ladder: every page decision climbs from the cheapest rung to the next only when unsure (owner, 10 Oct 2026)

**Verdict:** one escalation router for the whole applying flow (accounts, postings, forms). A rung that is unsure, contradicted or stalled hands the page to the next rung;
the top rung hands it to the person with the page's own sentence quoted. What a higher rung decided is kept for the lower rung (free next time) and counted, so the ladder gets
cheaper and measurable. Proposal page in Notion: "Proposal: any non-form outcome, decided by the AI from numbered page candidates" (Product).

## The gaps this spec closes
1. **Page-kind unsure goes DOWN, not up** (`confidence < 0.6` -> the structure rule decides). It must climb.
2. **No generic trigger** outside accounts: a posting after Apply with no form, a contradicted kept kind (`forgetKind`), an `other`, a stall.
3. **Learning is thin:** a higher rung's result is kept only for accounts. It must become the kept answer for the lower rung, verified, with a miss count.
4. **No digest rung** (3).
5. **No measurement:** nobody can say how often each rung is right.
6. **`other` is invisible** (log only).

## Design
### The router (`extension/ladder/climb.js`, pure; `desktop/lib/ladder.js` for caps, write-back and counts)
- Input: the rung that just answered and its **signal**: `confident` | `unsure` (confidence < MIN, or the judge said unsure) | `contradicted` (the page contradicts the kept answer) | `stalled` (a step was expected, nothing changed for N s) | `failed` (a control it named cannot be found).
- Output: the next rung to ask, or `person`. Rules: never skip upward past a rung that is off or capped; each rung has its caps (the existing 2 per page shape and 10 a day for rung 4 are the model; rung 3 gets its own, higher); every climb is logged ("ladder: kind unsure at rung 2 -> rung 3") with the shape, never text.
- The structure rule (rung 0) stays the floor when no AI is available; it never overrides a rung that answered.

### Rung 3: the numbered digest
- The extension adds **candidates**, found by structure only: sentences of the posting's main text (the `main`/`article` region first), links with their host, email-shaped and phone-shaped strings; each with its position (main, header, footer). At most 12, 160 characters each. No typed values, no query strings.
- The AI answers an **outcome** (the `apply_by` values, extended: form, email, phone, link, login_wall, expired, in_person, other) and a **verb** from a closed list (`tell_person [numbers]`, `press [number]`, `open [number]`, `none`), naming candidates **by number**. It never writes free text or actions; the floor "it is on the page" is true by construction.
- `press` and `open` are limited to what the extension may already do (the Apply button floors, never Submit, never a third-party sign-in, one press per tab and page). `tell_person` quotes the chosen sentences on the card.
- **Privacy line (owner, 10 Oct 2026: yes to adding it):** the AI now also sees up to 12 short lines of the employer's public posting text. No applicant data. The Intelligence page and its count get the entry in the same change.

### Bring the account-page logic to forms and postings
The triggers of `account-step.js` (unsure twice on the same page state, control not found) move into the router and are used by `fill-flow.js` for: page-kind unsure, no form after the Apply press (today the email report only), a kept kind contradicted, a fill that put nothing in (exists), a stall. Rung 4 (`closerLook`) gets a `scope` (`account` | `page` | `form`); its floors are unchanged: off unless "Do it for me", never Submit, never a consent on an application, never a bot check.

### Learning (write-back)
- A rung's answer that **worked** (the page changed as expected, or the person did not override it) is stored as the kept answer for that page shape in the lower rungs' cache, tagged `by` (which rung) and with `hits`/`misses`. One miss drops it (the existing contradiction rule), so a wrong write-back costs one more climb, not a wrong application.
- Per-shape counts (rung reached, outcome, hit or miss; no text) go to the existing token-gated pack path (k>=3); no second delivery path (public skeleton, private learned layer).
- An email outcome is still never kept for the shape (it names one posting's address); the **outcome class** may be kept as a hint that this shape asks for addresses (asked again with the digest).

### Measurement
- `desktop/e2e/ladder-fixtures/`: sketches and digests per outcome and per language (de, fr, en, it) with the expected outcome, including **confidently-wrong traps** (a closed notice on a page that still has a form). `npm run ladder-score` (plan path, no API spend) prints per-rung hit rate and the wrong-and-confident list. A change to a prompt or a rung is judged by this score.
- Run time: the rung reached per page shape in `app.log` and in the learned counts.

### `other` and unknown
`other` (and any outcome the code does not know) becomes a visible "needs your attention" card and a shape report, never silent.

## Data ownership
Nothing new about the person. Kept answers are a cache of what worked (rebuildable): `page-kinds.json` entries gain `by`, `hits`, `misses`. The application's state stays in `application-journey.js` (a new `stuck` value only if a rung ends at the person with a quoted sentence, reusing the `email` pattern). Counts carry shapes and numbers, no text.

## Floors (unchanged by this spec)
Never Submit; never a consent on an application; never a bot check or SMS code; never read a password field; one press per control per tab; no AI = nothing pressed; page and picture text are untrusted: only fixed answers and candidate numbers are read.

## Cost
Rung 3 about 1,500-2,500 input tokens per call, cached per page shape, asked only after rung 2 was unsure; rung 4 about 1.5k tokens for the picture plus the sketch, capped. On the plan path (Claude Code, Codex) it costs plan usage, not money. More calls only on pages that were unsure.

## Landing order (each its own push, tests first, flow-core claim each time)
A. One shared list of sketch fields (the endpoint cannot forget one again: frames, mails) + the digest field plumbing. B. Router + signals + rung 3 for page-kind (unsure -> digest -> person), with journey scenarios and a recorded page. C. Form/posting triggers into the router (no form after Apply, contradicted, stall) and rung 4 scope. D. Write-back + counts. E. Fixture set + `ladder-score`. F. The `other` card + shape report.

## Not in this spec
New kinds of action (sliders, captchas, widgets); a verify loop beyond the existing 3 actions per page; moving rung 5 (Claude takeover) into the loop.
